# Arcade game debug framework checklist

This checklist tracks implemented controls, not menu/catalog presence alone. A game is **complete** only after its meaningful variables and feature switches reach gameplay code, its practical event/phase/achievement tools are wired, reset/profile isolation is verified, and automated tests cover the controls.

## Framework foundation

- [x] Debug access uses the existing authorised admin/tester check.
- [x] Profiles and test-bot loadouts are stored separately in `debug-profiles.yml`, outside normal game settings and player stats.
- [x] Named profiles support create, duplicate, rename, load, save and delete; the default profile cannot be deleted.
- [x] Profile lifecycle edge tests reject blank/reserved/duplicate names and profile-cap overflow, prevent renaming or deleting Default, return to Default when deleting the selected profile, and verify duplicated profiles preserve variables, feature switches and complete bot loadouts.
- [x] Automated coverage saves an isolated bot count, team, kit and cosmetic selection for every game and verifies new named profiles do not inherit another profile's roster.
- [x] Automated coverage verifies common feature switches persist, reset and remain isolated across profiles for every game.
- [x] Reset to Defaults removes only the selected profile's overrides.
- [x] Menus separate profiles, feature switches, variables and bot setup for the currently selected game.
- [x] Numeric shared Arcade rules can be overridden for the active round; the menu marks these as restart-required.
- [x] The variable menu exposes only rules with an explicit production runtime consumer; persisted values are clamped to the rule's safe range and malformed integer conversions cannot crash gameplay.
- [x] Boolean gameplay switches are persisted as typed rule variables, reach the session override map, and have explicit immediate-versus-next-round metadata; live switches update the active rule value immediately.
- [x] Loading, creating, duplicating, renaming or deleting a profile during its active round refreshes explicitly immediate Boolean rule values and game feature switches, clears stale immediate feature values (including ones removed when deleting the prior profile), leaves restart-required numeric overrides untouched, and marks the round as debug-isolated.
- [x] Immediate feature-switch changes use one shared metadata decision for both menu labels and live runtime application; profile overlay tests cover clearing a feature value back to its intended consumer fallback.
- [x] Each rendered game feature now carries explicit `appliesImmediately` metadata consumed by the menu, while its shared decision remains available to the live profile updater.
- [x] Reset to Defaults clears per-profile rule overrides and test-bot count/loadouts, preventing legacy bot settings from being silently re-enabled.
- [x] Automated coverage walks every exposed game variable, sets it through the typed runtime override boundary, reads it back and verifies clearing restores its default; a source check keeps runtime override keys linked to the profile catalog.
- [x] A source-backed test verifies every catalogued variable has a production gameplay consumer, including the mode-scoped Monster Maze and dynamic Sneaky Assassins rule accessors.
- [x] A cross-module source check verifies each literal game feature switch shown in the debug menu is referenced by production code; dedicated behavior tests remain required for switches without direct runtime assertions.
- [x] Variable consumer checks include the separate Snake module, all SkyWars profile variables have runtime rule accessors, and tester profile changes affect Hoops target score, Wizards wand capacity, and mixed Turf Wars frontline step.
- [x] Automated coverage requires every individual game and Monster Maze mode to expose at least one game-specific runtime variable in addition to shared combat rules.
- [x] Shared feature switches cover kit unlock, invulnerability, fall damage and hunger; Bacon Brawl also has its unlimited-ability switch.
- [x] Achievement previews provide a game-scoped read-only menu entry for each achievement message/sound, while achievement preview mode also runs real conditions through wired Arcade award helpers and Snap; neither path persists unlocks.
- [x] Authorized testers can advance any shared Arcade start countdown, the live Draw My Thing turn, Master Builders build/review phase, Turf Wars phase, any supported shared round timeout, or the current Speed Builders, Plexball, Wizards, Snake, Snap, Monster Maze or Super Sploor phase; bot rosters are configured for the next round.
- [x] Every shared phase advance, including skipping the pre-round countdown, marks the active match as debug-only before returning to gameplay.
- [x] Authorized testers can restore only their own active-round health/hunger and clear fire/potion effects without invoking damage, scoring, or achievement paths.
- [x] Automated coverage verifies every event shown in a game menu has a matching production dispatcher, preventing catalog-only debug buttons.
- [x] A source-backed access test protects the authorised-tester gates on debug menus, bot menus, event actions, phase changes and feature mutations.
- [x] Per-game coverage rows below document the exposed controls, production consumers, immediate/restart timing, automated behavior checks, and intentionally fixed map/source data for every game and Monster Maze mode.
- [x] Every game exposes at least one event tool; menu entries have production dispatchers. Tools cover Draw My Thing hint reveal, Dragons spawn, Death Tag chaser conversion, One in the Quiver arrow refill, Paintball armour restoration, Spleef hunger restore, Wizards spell access, a normal selected-kit refresh for supported games, Wither Assault's minion-wave ability, Milk the Cow herd spawning, Sheep Quest sheep spawning, SkyWars generator TNT, Bacon Brawl meter fill, Castle Assault objective TNT, Heroes of GWEN minions, Runner position swap, Bomb Lobbers power-up waves, and a normal monster wave for all Monster Maze modes. Event availability and dispatcher coverage are automated; direct behavior tests remain listed by game below.
- [x] Every game's achievement preview list fits the menu; no registered entries are silently truncated.
- [x] Profile persistence/lifecycle and reset coverage includes variables, features and bot loadouts; tester-to-tester and game-to-game isolation is regression-tested for variables, selected profiles, bot counts/kits and reset. Authorised-only mutation, immediate-effect and round-restart reload behavior have automated coverage across every game.
- [x] Every setting listed below has a documented gameplay consumer and coverage check; remaining limitations are identified per game rather than hidden behind a Complete status.

Legend: **Partial** means the common profile framework exists but one or more game-specific controls, gameplay tests, or regression checks remain. **Pending** means that game's runtime is not connected to profile controls. **Complete** means practical controls and automated behavior/regression coverage are in place; live Paper acceptance may still be pending.

Debug-round persistence guard: configured debug rounds and rounds launched with a debug bot roster do not persist match stats or achievements. Authorized live feature changes, phase advances, vitals resets and active-profile resets also mark the round for isolation. Reset to Defaults clears active rule changes but keeps this guard enabled until the round ends. It covers shared Arcade stats, Snap, Speed Builders (including its standalone match and disconnect writers), Wizards, Plexball, Monster Maze, and Super Sploor; newly added direct progression paths must use the same guard.

Bot counts and per-bot team, kit, and cosmetic loadouts are now stored inside each tester's selected game profile. Duplicating or renaming a profile carries its roster configuration with it. Existing `test-bot-loadouts` values remain a fallback for the default profile during migration.

The common tester switches (all kits, invulnerability, no fall damage, and no hunger loss) are exposed in every game's debug menu. Invulnerability, fall, and hunger switches now also have runtime hooks for separately managed games when the authorized tester is in the active game world.
