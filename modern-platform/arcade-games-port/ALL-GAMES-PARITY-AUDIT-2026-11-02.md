## Scope and confidence

This is a static source and assurance-coverage audit of all 30 selectable identities in `ArcadePortGame`, comparing the archived 1.8 game implementations under `Plugins/Nautilus.Game.Arcade` (and the Nano Death Tag implementation) with the Paper 26.3 port. The three Monster Maze identities share one game engine. â€œReviewedâ€ means the modern path and available test/acceptance evidence were located; it does not mean the game has passed live-client acceptance. Evolution is included in the audit but is disabled in the current queue pending source-map clearance.

The merged shared combat/healing changes are cross-game safeguards. They do not establish feature parity for each game. This audit therefore tracks game-specific implementation and evidence separately. The current port is partly a large `ArcadePortManager` with inline per-game handlers, plus dedicated runtimes/modules; the centralized manager is a real maintenance and regression risk.

## Shared parity work still required

The next pass should turn the global defaults above into explicit regression checks for each game's combat profile: health cap, natural/food healing, hunger drain, exhaustion, ordinary melee damage, each custom weapon/ability damage, swing cadence, knockback, fall damage and environmental/void handling. The current generic layer cannot safely force identical values on games with custom weapons, spells or one-hit elimination. Each override needs a source value and a game-specific test/acceptance result.

## Exit criteria for a parity claim

1. Each enabled game has a 1.8 source entry point and a documented modern mechanic mapping, including explicit intentional differences.
2. A focused automated regression covers deterministic rules and damage/cooldown values where practical.
3. A Paper client acceptance record covers launch, representative complete match, elimination/respawn, score/win, cleanup, reconnect/disconnect and map/variant-specific behavior.
4. Disabled or asset-blocked games are labelled blocked/disabled rather than passed.

This audit identifies concrete coverage gaps; it is not a claim that every row has passed these exit criteria.
